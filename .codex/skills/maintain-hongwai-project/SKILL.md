# 维护红外小目标论文项目

帮助科研初学者以合理工作量推进毕业论文。当前目标是适合四区投稿的增量改进，不默认要求 SOTA 或所有指标超过 SCT；同时保持方法描述、对照和证据真实。不把分区当作固定指标门槛或录用保证。

## 从长期状态恢复上下文

1. 阅读 `E:/paperMainWork/hongwai_release_2026-10-22/private/长期任务文档/项目长期状态-CURRENT.md`。
2. 按当前任务读取其中链接的方案与结果，不默认加载全部历史材料。
3. 涉及代码、权重复用或实验执行时，运行本 skill 的 `scripts/collect_project_state.ps1`；它只采集本地状态，不访问服务器或修改文件。
4. 进入研究工作区后读取它的 `AGENTS.md`，直接核查受影响的配置、实现、日志与结果。HEAD 不包含未提交研究代码，不能单凭提交号声称实验已可复现。

长期目录不存在时，先尝试已知原始根路径，不盲目递归扫描磁盘或重新训练。路径迁移后更新权威入口。CURRENT 负责当前事实，日期化方案负责具体设计；避免多个文件各维护一套相互矛盾的进度。

## 尊重工作区与本轮任务范围

- 原始归档：`E:/paperMainWork`。研究代码、训练和新实验结果放 `E:/paperMainWork-lpsm-validation`；用户指定的原始根目录私有文档与 `.codex` 维护不等于允许改写历史模型和结果。
- 独立工作区历史分支为 `research/lpsm-validation`，使用前核实。保留用户未提交改动，不合并或推送原仓库，除非当前授权包含该动作。
- “先讨论方案”“保存文档”“看看效果”分别处理方案、文档、结果，不自行启动新训练。已有启动授权在对应范围内有效，不为例行可逆步骤反复询问。
- 用户此前允许使用三张空闲 A6000。启动时重新看占用，不能凭历史状态判断空闲，不能中断其他进程。默认数据、依赖、缓存与结果保存在服务器 `/DATA`，服务入口和路径见 CURRENT。
- 用户已允许 `private/` 中的研究文档与本 skill 进入私有 GitHub 仓库；目录名称不代表自动忽略。上传前核查实际文件，权重、预测缓存和环境继续排除，凭据不写文档或日志。此授权不包含将仓库改为公开。

## 研究与评估的关键区分

- 原始 SCT、四来源固定融合、普通修正器 Anchor、局部 LPSM、完整 LPSM 是不同层次的对照。提升相对谁必须说清楚。
- 四来源包含连续 SCT 系概率与阈值化 PConv/MSHNet 相关掩码；先核实缓存字段和预处理，不能一律称为四个软概率。原始 SCT 不在该四来源中。
- NUAA、NUDT、IRSTD 是三套基础数据集；SIRST3 为合并集，重叠结果不能作为独立泛化证据。
- 图像信息包括原始图像及其派生特征。设计“仅预测输入”消融时，检查整个特征生成链。
- 修正幅度限制、残差正则、局部分支、方向分支分别记录。当前方向实现不是官方 Mamba 状态空间模块；未测量成本不称轻量。
- 默认 mIoU 为主，Pd/Fa 等辅助；除非用户明确调整目标，不因结果改变主指标。阈值、过滤、来源和 checkpoint 在验证集选择，测试只用于冻结设置后的评价；如有历史测试选择或已查看测试的探索过程，保留披露。
- 旧 Fa 存在按面积值排除误报的缺陷，最新诊断另按区域编号核算并保存旧值。比较前检查口径，不能混用；验证集约束 Pd 不代表测试 Pd 完全相同。
- 大幅改善弱融合不自动证明特殊模块有贡献。保留强单来源、简单校正和普通修正器对照，按实际结果收敛论文主张；不将通用模块改名视为创新。

## 按请求推进工作

**讨论与计划**：优先复用已验证权重与预测，列出还缺什么；区分“只需重评”和“必须训练”。固定具体对照、输入、划分、预算与选择规则，避免顺手扩展新模型。

**实施与训练**：先检查配置及旧 launcher 的绝对路径、输出目录；写入新运行目录，保留历史证据。记录配置、来源权重与划分哈希、代码版本、种子、启动方式、日志、退出码和模型选择依据。先做与改动相称的检查，再执行已授权作业，不要求所有实验都增加重复测试。

**长任务**：后台运行并提供可用的监控或日志入口。确认实际进程与首条训练进度后才称“已启动”；记录 run ID、tmux 会话、输出路径和剩余步骤。用户要求启动后即可结束时，无需持续挂着等待。

**结果分析**：核查退出码、epoch、验证集选择和测试结果，不以文件出现或进程退出代替成功。用同口径表格解释收益与局限，保留修复、误伤及负例。先用通俗语言给结论，再给支撑数字；除非用户要求，不自动启动下一轮。

## 实质性工作后维护长期状态

在同一任务中更新 CURRENT 的变化事实、证据路径、限制、进行中任务和下一步。以下情况属于实质性变化：研究方向改变、运行方案冻结、实验真实启动/失败/完成、指标或来源被纠正、核心设计被保留或放弃、工作区或服务器路径变化。

- 重写过时事实，详细分析放日期化文档并链接；不不断追加对话流水账。
- 明确区分候选想法、计划、已启动、已完成、已核验；未验证的服务器占用和可达性不写成当前事实。
- 数值链接到 JSON/CSV、配置或日志，写清数据集、验证/测试、阈值规则和单位。保留历史原始结果，不静默覆盖。
- 讨论结论与下一步实现状态分别记录。仅有讨论或文档授权时，下一轮训练仍写为待实施。
- 小型格式改动不需要重写整份状态；本 skill 不要求额外发布、Git 提交、全量审查或新增审批流程。

交付时说明完成内容、验证结果和实际剩余工作。后续可使用 `$maintain-hongwai-project` 显式调用本 skill；默认保留自动匹配。
